# ADR-0007: OCR Confidence, Approved Memo Export, and API Protection

- Status: Accepted
- Date: 2026-09-18

## Context

Domain Copilot must process both digitally generated and scanned contracts.
Direct text extraction from a scanned PDF can return no usable text, while OCR
can introduce recognition errors. The system therefore needs to preserve
extraction confidence instead of treating all extracted text as equally
reliable.

The application also generates draft legal-risk memos. A draft memo must not be
exported as a final-looking DOCX report without explicit Counsel approval and
traceable source evidence.

Finally, the API accepts uploaded documents and can initiate database and LLM
work. Baseline protections are required against unauthenticated access,
unbounded request bursts, invalid uploads, and instructions embedded inside
retrieved document text.

## Decision

### OCR and confidence

PDF ingestion first attempts direct text extraction. When a page has
insufficient direct text, the Infrastructure OCR adapter uses Poppler to render
the page and Tesseract to extract text with confidence information.

Each `DocumentChunk` persists `ExtractionConfidence` and derives
`LowConfidence` from the configured ingestion threshold. Confidence is carried
into downstream retrieval, review, and DOCX source references.

### Approved DOCX export

A `ReviewMemo` persists its citations and risk findings as relational records:

- `ReviewMemoCitations`
- `ReviewMemoRiskFindings`

DOCX export uses these persisted records, not source labels generated by the
LLM or parsed from Markdown.

`IReviewMemoExportService` must call the existing approval guard before
rendering. A memo can be exported only when:

1. its status is `Approved`;
2. it has persisted source citations; and
3. every source-backed risk finding maps to a persisted citation.

The renderer is an Infrastructure adapter using `DocumentFormat.OpenXml`.
Application owns export contracts and approval rules; it has no OpenXML SDK
dependency.

### API protections

All non-Swagger API routes require an `X-Api-Key` header. The configured API
key is loaded from environment configuration and compared in constant time.

The API uses fixed-window rate limiting:

| Policy | Limit | Scope |
|---|---:|---|
| `expensive-operations` | 10 requests/minute | Ingest, Answers, LegalReviews, embedding indexing |
| `state-changing` | 20 requests/minute | Memo actions and DOCX export |
| `retrieval` | 60 requests/minute | Retrieval search |

Uploads are restricted to PDF, DOCX, and TXT, with a maximum request size of
20 MB.

Prompt-injection controls treat questions and retrieved contract text as
untrusted data. System rules are separate versioned prompt assets, and
grounded answers are accepted only when their citations reference retrieved
chunk IDs.

## Consequences

- Scanned contracts become ingestible while confidence remains visible to
  counsel and downstream services.
- A generated memo cannot become a downloadable report without a human
  approval decision and stored evidence.
- API clients must send `X-Api-Key`; Swagger remains reachable for discovery,
  but protected API calls require the header.
- Rate limits reduce accidental LLM/database bursts but are application-wide
  until Day 11 adds user identities and Lawyer/Counsel roles.
- OCR tooling is an Infrastructure dependency. Deployments must configure the
  Tesseract and Poppler executable paths through environment variables.
- File-extension validation is not malware scanning; production deployment
  should add malware and MIME/content validation upstream.
